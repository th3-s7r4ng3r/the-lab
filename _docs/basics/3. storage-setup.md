# Secondary HDD Setup (Storage Nodes)

Follow these steps for any node with a secondary high-capacity HDD to prepare it for local storage and Kubernetes Persistent Volumes.

### 1. Identify and Partition the Drive

Identify the target drive (typically `/dev/sdb`). Create a GPT partition table and allocate 100% of the space to a single primary partition.

```bash
# Identify the disk
lsblk

# Create a GPT partition table
sudo parted /dev/sdb mklabel gpt

# Create a single partition using all available space
sudo parted -a opt /dev/sdb mkpart primary ext4 0% 100%
```

### 2. Format and Reclaim Reserved Space

Format the new partition as ext4. By default, Linux reserves 5% of the disk for the root user; set this to 0% to maximize usable storage for data.

```bash
# Format the partition
sudo mkfs.ext4 /dev/sdb1

# Reclaim the 5% reserved space
sudo tune2fs -m 0 /dev/sdb1
```

### 3. Configure Persistent Mounting

Create a mount point and update the file system table (`fstab`). The `nofail` option is used to ensure the system continues to boot even if the secondary drive is physically disconnected or fails.

```bash
# Create the mount directory
sudo mkdir -p /data-drive

# Retrieve the Partition UUID
UUID_VALUE=$(lsblk -dno UUID /dev/sdb1)

# Add entry to /etc/fstab for automatic mounting
echo "UUID=$UUID_VALUE /data-drive ext4 defaults,nofail 0 2" | sudo tee -a /etc/fstab

# Mount the partition
sudo mount -a
```

### 4. Set Permissions

Adjust ownership and permissions to allow the standard user to read and write to the root of the mount point.

```bash
# Change ownership to the current user
sudo chown -R $USER:$USER /data-drive

# Set directory permissions
sudo chmod -R 775 /data-drive
```

### 5. Verification

Verify that the drive is mounted correctly and that the reserved blocks have been successfully removed.

```bash
# Check mount status and available capacity
df -h /data-drive
```

## Additional Notes

- Since two nodes have same HDD capacity, a new longhorn storage class will be created for replication between the two nodes. This will be used for workloads that require high availability and higher capacity. A new directory named `longhorn-sc-hdd` will be created under `/data-drive` in each node.
- By default, the cluster uses another longhorn storage class that utilizes the internal SSDs of each node for faster performance with replication between three nodes. This will be used for critical workloads that require high performance and can tolerate lower capacity. A new directory named `longhorn-sc-ssd` will be created under `/` in each node.

Longhorn is a distributed block storage system for Kubernetes that allows you to replicate and store persistent volumes across multiple nodes in the cluster. It is a container-native storage solution that is designed to be used with Kubernetes and can be easily deployed and managed using Terraform.
